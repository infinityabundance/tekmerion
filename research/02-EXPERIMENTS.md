# Preregistration — E1 to E5

Written before any run whose result could be claimed. Each experiment states its
hypothesis, arms, endpoints, budget, stopping rule, and **kill criterion**. A null is a
result only if the kill criterion was fixed in advance; otherwise it is a bug report.

Common protocol, from the brief and not negotiable here:

- Freeze by digest: benchmark commit, HOL Light commit, `TacticTrace` tag, `timeouts.json`,
  hardware, model name and generation settings.
- Contamination control: run both the **verbatim** and the **obfuscated** query variants,
  and run a memorisation probe per model. A contaminated arm is withdrawn, not adjusted.
- Equal budgets: identical kernel-call budget, wall clock, and hardware across arms. Report
  cost next to every solve rate.
- Statistics: repeated seeds; medians and quartiles; Vargha–Delaney A12; Mann–Whitney U;
  bootstrap intervals; Holm–Bonferroni across a family. Export raw series.
- Every number in a report is generated by a script from receipt files. No hand-typed
  numbers.

## E1 · Failure-side trajectory instrument

**Why first.** Every later experiment that mentions residuals, doomed branches, or repair
needs labelled failures. `TacticTrace` does not produce them, deliberately.

**Hypothesis.** A tactic-level wrapper that records failures produces a corpus that is
(a) bit-identical to `TacticTrace` on every success record, and (b) sufficient to compute
exact doomed-branch labels at kernel ground truth.

**Construction.**

1. Build HOL Light with `HOLLIGHT_USE_MODULE=1` and OCaml 5.5 (required by `TacticTrace`).
2. Generate `kernel_wrapper.ml` per `TacticTrace/build-hol-kernel.sh`.
3. In the generated tactic wrapper, wrap the tactic application in a handler that records a
   failure record before re-raising. The record must not change HOL Light's exception
   behaviour.
4. Record for failures: `goal_before`, tactic name and source location, subgoal index that
   failed, exception constructor and payload, number of subgoals produced before failure,
   and the wall-clock cost of the failed application.

**Conformance test (this is the gate).** For a proof script with no failures, the success
records from our wrapper and from stock `TacticTrace` must serialise identically modulo the
added failure field. Any diff is a bug in our wrapper. Report the diff count; it must be 0.

**Corpus.** Final human proofs contain no failures, so the corpus must come from proposer
rollouts. For each of N sampled tasks, run the baseline proposer K times, record every
step, and keep the terminal failure. Target N=100 tasks × K=8 attempts as the pilot
(the brief's own 100-obligation pilot, but with the right object).

**Endpoints.**
- `conformance_diffs` (must be 0).
- `failure_events` captured per attempt.
- `replay_exactness`: replaying a captured failure event reproduces the same exception and
  the same `goal_before`.
- `label_agreement`: the derived doomed-branch label agrees with a hand-labelled sample of
  50 trajectories.

**Kill criterion.** If conformance diffs are non-zero and not fixable without changing HOL
Light semantics, the instrument is wrong; stop and fix before any downstream experiment.

**Artefact.** Schema plus loader, released with the harness, so failure trajectories are
usable by people who do not adopt Tekmerion.

## E2 · Functional-correctness category

**Why this target.** The aggregate is contested at 6.35%/10.26% and the FC category is at
0/864. A first category result is better than a marginal aggregate result, and it is
adjudicated by the authors.

**Hypothesis (revised).** At equal budget, **step-level construction** raises the FC solve rate
above every published baseline, which is zero on the original 864 tasks. The earlier
lemma-recall hypothesis is withdrawn: the harness replaces every proof with `CHEAT_TAC`, so all
preceding lemmas are already available in each task's context. The bottleneck is that FC proofs
are long symbolic-simulation scripts that a one-shot answer cannot produce.

**Arms (all on the same frozen corpus, same timeouts, same hardware).**

| Arm | Contents | Purpose |
|---|---|---|
| A0 | `prompt-basic.txt`, one attempt | Reproduce the 6.35% class |
| A1 | Same prompt, 5 attempts with checker feedback | Reproduce the 10.26% class; sanity check |
| A2 | A1 + certificate tactics for bit-vector/arithmetic subgoals | Isolate certificate engines |
| A3 | A2 + ARM→x86 (then x86→ARM) sibling transfer of the system's own kernel-accepted proofs | Cross-architecture transfer |
| A4 | **Step-level harness**: fixed simulation skeleton, model supplies invariants, bounds and case splits, every step checked | The primary thesis |
| A5 | A4 + per-step residual cutoff (term size, carry-chain depth, open side conditions) | Isolate the DSFB contribution |

A0 and A1 are **reproduction arms**. If they do not land near the published numbers, the
environment is wrong and no other arm may be interpreted.

**Primary endpoint.** Strict `OK` count on the FC category at Pass@1, with equal budget.
Secondary: total `OK` across all 2,622; cost per `OK` (kernel calls, wall clock, tokens);
`CHEATING` count (must be 0).

**Controls.**
- Same solved-task set is re-checked with `collect-verdicts.py`; any `CHEATING` or
  `SYNTAX_ERROR` asymmetry is reported.
- Obfuscated-variant deltas reported per arm.
- Human-proof leakage check: for each solved task, test whether the model reproduces the
  human proof verbatim; report the exact-match rate.

**Stopping rule.** Two independent seeds per arm on a 200-task FC subset; if the rank order
is stable, run the full category. Sequential testing with a fixed total budget; no peeking
beyond the preregistered checkpoints.

**Kill criterion.** If the step-level arm produces no kernel-accepted FC proof at equal budget,
stop that line and reallocate. If A1 cannot run because the exact model is unavailable, record
the reproduction as blocked; never substitute a different model and call it a reproduction. If
A1 does run and does not land near the published 10.26% class, the harness is wrong: fix and
restart, do not interpret.

**What would make this a real frontier claim.** A0/A1 reproduced, A4 > A1 on FC at equal
budget, every proof replayed by HOL Light, zero axiom additions, and a leaderboard
submission. Anything short of that is `SCOPED_OBSERVATION`.

## E3 · Byte binding and revocation on the real corpus

**Why.** `SOUNDNESS.md` names the gap: no check that downstream reassembly yields the bytes
the proofs were about. The crate implements the typed model; this experiment puts real
bytes through it.

**Hypothesis.** Reassembling s2n-bignum `.S` files in a foreign project layout with a
different assembler version produces object bytes that differ from the verified bytes for a
non-zero fraction of routines, and typed revocation flags exactly the affected theorems
while leaving semantic revocation untouched.

**Construction.**

1. Build `s2n-bignum`; extract `.text` (and `.rodata`) bytes per routine with the existing
   OCaml loader, and hash them.
2. Reassemble the same `.S` files in a fresh directory with a different toolchain/version
   or layout; hash again.
3. Compare hashes per routine. Report the fraction that differ.
4. For each differing routine, determine whether the difference is semantically relevant by
   replaying the proof against the new bytes (or by a deterministic byte-level diff plus
   disassembly comparison, since the loader semantics may not permit a direct replay).
5. Feed the real digests into `tekmerion` with edges: spec=Semantic,
   object=Subject, kernel=Attestation.

**Endpoints.**
- `byte_drift_rate` per routine.
- `revoked` count and severity split.
- `precision`: of the revoked theorems, how many are genuinely inapplicable (ground truth
  from step 4).
- `recall`: must be 1.0 by construction; assert it.
- `silent_mismatch`: routines whose bytes differ but whose proof still applies. These are
  the interesting cases and must be listed individually.

**Kill criterion.** If byte drift is zero across the corpus, the reassembly gap is not
reachable in practice under these conditions — record that as the finding, scope it to the
toolchain tested, and do not claim a gap.

**Note.** E3 does not require an LLM and does not need the FC track. It can run in parallel.

## E4 · Goal-state forecasting (R3 for free)

**Why.** `TacticTrace` records `goal_before` and `goals_after` for successful tactic
applications. Predicting the post-tactic goal state and scoring the error is a
white-box calibration signal that needs no new instrumentation.

**Hypothesis (narrowed).** A model's prediction error about a tactic's effect identifies when
its future recommendations are unreliable, and using that signal online raises kernel-accepted
proofs at equal compute. Post-tactic state prediction is already published (3D-Prover, arXiv
2410.11133); novelty is claimed only for online per-region error as a trust signal on an
industrial machine-code corpus. See `receipts/forecast-prior-art.md`.

**Construction.**

1. From **C1's unsampled stream**, build `(attempt_id, step, goal_before, tactic, goals_after)`
   tuples. Stock `TacticTrace` output is unusable here: it keeps at most 20 records per tactic,
   prefers the shortest goals, and records no step order, which biases forecast error downward.
2. Ask the model to predict `goals_after` from `goal_before` and `tactic` only.
3. Score with a structural distance that does not pretend to be a metric space:
   subgoal-count delta, term-size delta, leading-connective match, multiset distance over
   head symbols, and a normalised edit distance on pretty-printed goals. Report each
   separately; do not sum them into one "residual" without an ablation.
4. Fit a per-motif predictor of next-step success; compare with baselines.

**Baselines.** Tactic frequency; goal size; a value model trained on the same traces; an
untrained model's self-reported confidence.

**Endpoints.** Calibration (Brier / log loss) per motif; top-k tactic-family accuracy;
solve-rate lift when the predictor is used to prune, at equal budget.

**Kill criterion.** If forecast error adds no lift over goal size and tactic frequency with
overlapping intervals, the R3 channel is not informative on this corpus. Report it — that
is a useful negative about the DSFB thesis, and publishing it early is cheaper than
publishing it late.

## E5 · Definitional differential fuzzing (gated on C1)

**Why.** The CVE was a definitional bug, and the PoC is reproducible.

**Construction.** Take Kernel A's declaration checker. Generate definitional mutants:
ill-typed nested inductives, projection/type mismatches, duplicate binders, shadowed
definitions, parameter-count errors, and hash-collision padding. Score the checker by
**refusal-site mutation**: for each refusal site, disable it and confirm a mutant is caught.
Use the CVE PoC as a known-positive.

**Endpoints.** Catch rate over the mutant family; refusal-site mutation score; false-accept
count (must be 0); false-refuse rate on a clean corpus (must be reported, not assumed 0).

**Kill criterion.** A single false accept on a well-formed declaration invalidates the
checker for this purpose and is a STOP condition, per the brief's escalation rules.

**Prior art obligation.** Cite arXiv 2608.26183 for refusal-site mutation and state
explicitly what is new: the target (definitional checking of a proof kernel), not the
technique.

## Reporting template

Every result is written as:

```
Claim:      <one sentence, no adjectives>
Comparator: <exact system, arm, commit, budget>
Evidence:   <receipt paths, digests>
Statistic:  <value, interval, test, correction>
Scope:      <benchmark, platform, kernel version>
Non-claims: <what this does not show>
Reproduced: NO | INTERNAL_ONLY | EXTERNAL_REVIEW_PENDING | INDEPENDENTLY_REPRODUCED
```

`INDEPENDENTLY_REPRODUCED` requires someone outside the programme to rerun the frozen
package. Until then, the honest label is `EXTERNAL_REVIEW_PENDING`.
